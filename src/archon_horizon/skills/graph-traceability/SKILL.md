## HomAlgDB rules

Read the repository root `AGENTS.md` before work. P-1: formalize the document's
objects, hypotheses, generality and statement order literally; a Mathlib counterpart
is metadata, never a replacement for the document's statement. P-2: follow the
document's proof route in the verbatim `## Proof`, its `[uses …]` annotations and
`deps.proof`; do not replace a difficult proof with a convenient stronger theorem.

Node headers are the source of truth. `blueprint/` and `hgraph/config.yaml` are
generated by `homalg blueprint-tex`; edit the node header, never generated `.tex`.
Build only through `horizon check` (the shared build lock); never invoke `lake build`
or `lake env lean` directly at the repository root. The task's explicit write scope
is binding: changes outside it are reverted. Preserve node IDs and paths.

Reviews use exactly `satisfactory`, `partial`, `mismatch`, `unverified`, or
`needs-adjudication`. Results the document uses without proving belong in `Cited_`
nodes. Send problems to the local inbox; open disputes with
`homalg dispute open <NodeId> --kind <kind> --reason "…"`. Do not open GitHub Issues
during a run. An unreadable page is `document-error`, addressed to `human` with
`--node <NodeId>` when known.

Read the tracked `horizon/review-policy.yaml` and repository
`docs/REVIEW_POLICY.md`. If independent agent reviews are explicitly enabled,
routine foundation, first-definition and explained-deviation reviews may proceed
through `homalg foundations review`, `homalg review-fidelity --session ...
--author-session ...`, and `homalg plan --early-review-ok --session ...
--author-session ...`. Actual author/reviewer sessions must differ; inspect source
evidence and record current hashes. Never invent an independent reviewer or treat
an agent verdict as human approval. Missing or disabled policy keeps the original
human review gates. Formalization sessions cannot change this policy themselves.

Only humans run `homalg dispute confirm`, `homalg dispute resolve`,
`homalg foundations confirm`, `homalg review-fidelity --human`,
`homalg transcription resolve`, or the early-review command without agent session
provenance. Agents must not create, replace or remove genuine human confirmations,
fidelity locks, transcription reviews, or confirmed/resolved dispute records.
Escalate unresolved mathematical or source disagreements; do not manufacture a
satisfactory review to advance a task.

Commit only to the engine ledger through `hgit` (`$HORIZON_GIT`). Never run
`git add`, `git commit`, or `git switch` against `<root>/.git`. Publishing uses
`homalg submit`; `homalg` manages the working branch. Keep private PDFs, page images,
page transcriptions and raw run logs out of public files and remote status data.

# Graph traceability

Use [[hgraph]] commands on one named project and scope the review to the
affected cone when possible. The graph is a useful map, not an independent
proof checker.

## Inspect

Run sync and read its complete output. Check:

- unresolved labels, `\uses`, `\lean` names, duplicate declarations, and
  stale/dangling nodes;
- edge direction and whether statement versus proof dependencies are recorded;
- node status, source boundaries, chapter membership, and actual consumers;
- closure/frontier counts against the intended theorem route;
- `lean_status` against the artifact evidence, rather than treating a source
  scan as a kernel check;
- generated timestamp/order churn versus substantive node or edge changes;
- roadmap/task references and status transitions for the same milestone.

Inspect the cone of a claimed terminal node, not only aggregate counts. A large
number of closed helpers can coexist with an empty headline node; an apparently
clean snapshot can hide an untracked or stale duplicate.

## Report and preserve

Include project, graph revision, command output summary, counts, and exact node
ids. Separate authored defects from generated churn and concurrent changes.
Never stage or revert a broad generated rewrite merely to make statistics look
clean. Use a node comment for a local mapping fact and an inbox issue for
cross-project or status coordination. Pair with [[blueprint-integrity]],
[[verification-evidence]], and [[provenance-isolation]].

## HomAlg audit target

Compare node headers against generated `.tex`, and declared `deps` against verified
Lean dependencies (`deps_diff`). A missing/stale graph calls for regeneration.
Do not request manual blueprint authorship; report the exact header defect instead.
